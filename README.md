# Human skin permeability: source variation and calibration

Analysis code for **From study variation to calibration: human skin permeability QSPR using shared compounds**.

This project examines variation in published human skin permeability measurements and evaluates whether compounds shared with reference data can calibrate predictions for other compounds from a new literature source. Analyses use the Cheruvu, HuSkinDB, and SkinPiX datasets.

The workflow includes hierarchical variance decomposition, molecular quantitative structure-property relationship (QSPR) models, leave-one-compound-out validation, calibration of held-out sources, cross-dataset transfer, bootstrap uncertainty, and retrospective calibration-failure diagnostics.

## Requirements

- R, including the `Rscript` command.
- R packages: `readxl`, `lme4`, `ggplot2`, and `patchwork`. The figure script requires a version of `patchwork` that provides `free()`.
- Python with RDKit installed. The interpreter must be available as `python` on the command line because the SkinPiX preparation script invokes that command.

Install the required R packages if needed:

```r
install.packages(c("readxl", "lme4", "ggplot2", "patchwork"))
```

Activate the Python environment containing RDKit before running the pipeline. Check it with:

```bash
python -c "import sys, rdkit; print(sys.version); print(rdkit.__version__)"
```

### Software versions

Software versions used for the analysis are recorded in `R/results/sessionInfo.txt`, generated by `run_all.R`. This file includes the R environment, required R package versions, Python version, and RDKit version.

## Project layout

Place `README.md` and `run_all.R` in the project root, alongside the `R/` and `data/` directories.

| Path | Contents |
| --- | --- |

## Input data

The pipeline requires these files, with the filenames and original column headings preserved:

| Filename in `data/raw/` | Dataset source |
| --- | --- |
| `cheruvu.xlsx` | Cheruvu et al. (2022), *Data in Brief*. [doi:10.1016/j.dib.2022.108242](https://doi.org/10.1016/j.dib.2022.108242) |
| `huskinDB.csv` | Stepanov et al. (2020), *Scientific Data*. [doi:10.1038/s41597-020-00764-z](https://doi.org/10.1038/s41597-020-00764-z) |
| `skinpix.xlsx` | Chedik et al. (2024), *Scientific Data*. [doi:10.1038/s41597-024-03026-4](https://doi.org/10.1038/s41597-024-03026-4) |

Permeability is analyzed as base-10 logarithmic permeability, with Kp expressed in cm/h. Preparation scripts perform the unit conversions, filtering, and identity assignment described in the manuscript. Molecular weight and Crippen logP for cross-dataset transfer are calculated using RDKit.

## Run the analysis

From a terminal in the project root:

```bash
Rscript run_all.R
```

The runner checks required files, R-script syntax, R packages, and Python/RDKit availability before clearing generated outputs. It creates output directories as needed, launches each analysis script in a separate R session, and stops if any script returns a nonzero exit status.

**The runner deletes existing generated files before rebuilding.** It clears:

- `data/processed/`
- `R/results/`
- `R/tables/`
- `R/figures/`, except files named `00_GA.pdf` (case-insensitive)

Raw data in `data/raw/`, the analysis scripts, the README, and manuscript source files outside those generated directories are preserved. Keep any files that must be retained outside the generated directories. Outputs are overwritten in place; dated backups are not created.

## Execution order

| Order | Script | Purpose |
| --- | --- | --- |
| 1 | `01_prepare_describe_cheruvu.R` | Prepare Cheruvu data |
| 2 | `10_fit_diagnose_cheruvu_hierarchical.R` | Fit and diagnose variance models |
| 3 | `20_fit_cheruvu_qspr_models.R` | Fit molecular QSPR specifications |
| 4 | `21_validate_cheruvu_qspr.R` | Validate Cheruvu models and perform sensitivity analyses |
| 5 | `30_prepare_describe_huskindb.R` | Prepare HuSkinDB data |
| 6 | `31_fit_validate_huskindb.R` | Replicate variance analysis and calibrate held-out sources |
| 7 | `32_compare_calibration_methods.R` | Compare conventional and hierarchical calibration |
| 8 | `40_prepare_describe_skinpix.R` | Prepare SkinPiX, match compounds, and invoke the Python descriptor script |
| 9 | `41_validate_skinpix_transfer.R` | Evaluate transfer from HuSkinDB to SkinPiX |
| 10 | `50_falsification_checks.R` | Compare prediction settings and target-source versus other-source calibration |
| 11 | `60_uncertainty_analysis.R` | Estimate bootstrap confidence intervals |

| 13 | `99a_make_tables.R` | Generate manuscript tables |
| 14 | `99b_make_figures.R` | Generate manuscript figures |

All R scripts in this table are located in `R/`. The Python descriptor script is called automatically by script 40 and does not need to be run separately.

## Outputs and logs

- Main manuscript tables are written to CSV files beginning `01_` through `05_` in `R/tables/`.
- Supplementary table files use the `S` prefix. The failure analysis is divided between `S15a_calibration_failure.csv` and `S15b_calibration_failure_decomposition.csv`.
- Main and supplementary figures are written as PDFs in `R/figures/`.
- `R/results/run_status.txt` records completed steps and the final run status.
- `R/results/sessionInfo.txt` records environment versions.
- `R/results/logs/` contains one combined output/error log per R script.

The graphical abstract is a manually prepared asset; the pipeline preserves it but does not regenerate it. The runner generates analysis outputs, not the compiled manuscript.

If a step fails, inspect its log in `R/results/logs/`. Earlier steps may already have produced files; a failed run is not a complete output set. Running `run_all.R` again clears generated outputs and starts the full analysis again.

To rerun an individual script without automatic cleanup, run it from the project root, for example:

```bash
Rscript R/99a_make_tables.R
```

Individual scripts require the processed data and intermediate results generated by their preceding steps. Regenerate downstream outputs after changing an upstream analysis.

## Reproducibility

Random sampling and bootstrap analyses use seeds specified in the scripts. The uncertainty analysis requests 2,000 bootstrap replicates. Runtime depends on the computing environment, particularly for repeated mixed-model fitting and the pairwise source-control analysis.
